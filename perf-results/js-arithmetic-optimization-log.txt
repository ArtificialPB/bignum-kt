=== DISCARDED ATTEMPT — 2026-08-13 ===
Change: Replace the Kotlin binary-exponentiation loop with ECMAScript's native `BigInt ** BigInt`
operator.

Result: Rejected before benchmarking. Kotlin's embedded JavaScript expression parser reports
`Power expressions are not supported yet`, so the candidate does not compile. The existing loop
was restored; runtime evaluation workarounds were not pursued because they add parsing overhead and
weaken static checking.

=== RUN 3 — 2026-08-13 ===
Change: Compute `divideAndRemainder()` with one host division, then derive the exact remainder as
`dividend - quotient * divisor`, instead of executing independent host `/` and `%` operations.

Validation source:
- `./gradlew :bignum:jsNodeTest :benchmarks:jsArithmeticSmokeBenchmark --rerun-tasks --no-configuration-cache`
- `benchmarks/build/reports/benchmarks/arithmeticSmoke/2026-08-13T17.04.26.57078/js.json`

- divideAndRemainderMethod: 0.093/0.563/2.387 -> 0.099/0.358/1.595 us/op

Observed effect:
- Medium and large operands improved by about 36% and 33% respectively by eliminating the second
  expensive division.
- The small profile regressed by about 6%, where multiplication and subtraction cost slightly more
  than a second division. The large real-world win outweighs this 0.006 us absolute small-value cost.
- Division, remainder, and unrelated arithmetic operations stayed within their prior benchmark band.
- All 1,224 JS tests passed.
